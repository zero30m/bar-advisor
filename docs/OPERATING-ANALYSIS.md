# 经营分析 v3.1（2026-11-02）

无需更改千问代码或部署前端。接口仍为原有report/state，summary仍为字符串，支持原版分段展示。刷新页面或进入复盘读取新结果即可。

## 计算与证据

- 原始账单金额继续以整数分保存，分析输入统一明确换算为元。
- 日报：较前一天、上周同日、去年公历同日；周报：近七天对前七天、去年公历同日期区间。收入增减、支出变动、现金差额变动由代码计算。
- 两个期间必须完整记账才计算增长率。漏记不算零营业额；对照为零时仅显示绝对增额，不计算无限增长率。闰日没有去年同日则不强行匹配。
- 标注周末、法定放假调休区间、补班日；日历类型不同的对照提示不可直接归因。日常营业日和法定工作日不是同一概念。
- 至少三个历史同类已记账日时，提供过去二十八天同类日收入均值参考。样本不代表完整营业记录。
- 读取门店设置：月净利润目标=投资额/目标回本月数。按10%、15%、20%假设净利率计算所需月营业额。
- 已记录当月收入/目标营业额给出已记录进度；同时给出日历进度。漏记时不推算剩余日均需求；无漏记时按剩余自然日分摊目标差额，明确不是营业日或客流预测。
- 以10%情景目标营业额保持不变，分别算10%、15%、20%假设利润率下的静态回本月数；不拿已记录现金差额当真实利润率，不承诺实际回本。

## AI职责与成本

AI读取结构化证据，选择重点解释和具体核查动作，不重新计算金额。程序生成全部数值段落；模型解释若含不允许的金额、比例或明显无依据开业推断，则舍弃该片段。无有效建议时使用基于缺失记录、目标进度、负差额等实际条件的确定性建议。

相同账单、日期、设置与算法版本继续缓存。日期、历史对照账单或门店设置变化会改变分析输入；保存或删除账单/设置会使相关复盘失效。不为随机改写而额外调用模型。每日20次限制不变。

## 节假日数据来源与边界

已核验2025和2026年官方安排，保存在business-calendar.mjs，不在请求时抓取外网。
- 2025：https://www.forestry.gov.cn/c/www/szxx/594663.jhtml
- 2026：https://www.beijing.gov.cn/cs/gncs/zcwj/202603/t20260327_4568275.html

其他年份明确显示节假日尚未核验，只能计算星期，不能假定无假日。后续需按官方通知更新日历。公历同比不保证农历节庆或星期一致。

## 验证

必要自动测试覆盖金额分元换算、负数/小数、七天范围、同比环比、缺失记录、零分母、600万/12月回本情景、目标月数变化、节假日/调休及未知年份。部署前已备份数据库，仅清理旧复盘缓存，未修改账单、门店设置或营销记录。
